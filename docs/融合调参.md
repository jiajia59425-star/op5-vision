# 雷达 + 行人视觉融合：上机调参

服务只检测 **person**（COCO 类别 0）。植物和其他类别在检测后处理里就被丢掉，融合模块会再滤一次。预览在 `http://<香橙派IP>:8081/`，原配网页面的 iframe 也指向这里。

画面上：

- 绿框：视觉行人
- 黄点：雷达目标投影
- 蓝圈：已确认融合航迹，旁边有 `id`、距离和来源（`fused` / `vision` / `radar`）

参数都在 `config/fusion.json`。改完重启：

```bash
python3 -m vision.service --config config/fusion.json
```

RK3588 上把 `models/yolov8n.rknn` 放到仓库里即可走 NPU（`rknn-toolkit-lite2`，三核 `rknn_core_mask=7`）。没有 rknn 文件时，如果有 `models/yolov8n.onnx` 和 OpenCV，会退到 CPU。权重不要提交进 git。

雷达默认是海凌科 LD2450：串口 256000，`/dev/ttyUSB0`。协议按厂家 V1.03（最高位 1 为正）。别的模块把 `radar_mode` 改成 `jsonl`，向 UDP `8090` 发：

```json
{"t": 12.34, "targets": [{"x": 0.2, "y": 3.5, "vx": 0.0, "vy": -0.3, "id": 1}]}
```

`x` 向右、`y` 向前，单位米。`t` 要和相机用同一套 `time.monotonic()` 秒；如果是 Unix 时间戳，程序会丢掉它并改用到达时刻，这时主要靠 `radar_time_offset_s` 补偿。

## 为什么以前对不齐

仓库里原来没有融合程序，页面只是嵌了 8081 的画面，检测类别、雷达坐标和时间戳都没有参与跟踪。下面几项是这类融合实际会漂的原因，程序里已经按这个处理，调参时不要再绕回去：

1. 把雷达的 x/y 当成像素，或者当成相机的 x/y。雷达是 x 右、y 前、z 上；相机是 x 右、y 下、z 前。
2. 用最新一包雷达去配当前图像。人在动的时候两者差一两百毫秒，点会拖在身体后面或旁边。
3. 不设门限，最近的点和最近的框硬配。旁边的杂波、以及以前的植物框，会把航迹拽走。

## 建议的标定顺序

先让一个人站在相机正前方约 4 米，雷达和相机都要看到。

1. **内参**。已知水平视场角时可以先近似：`fx = fy = 0.5 * width / tan(水平视场角/2)`，`cx = width/2`，`cy = height/2`。有棋盘格再用标定结果替换。改完把 `width/height` 设成实际画面尺寸，并把 `calibrated` 设为 `true`。
2. **安装位置**。`tx_m/ty_m/tz_m` 是雷达原点在相机坐标系的位置（米）。雷达在相机右边则 `tx_m` 为正；相机系 y 向下，雷达在相机下面则 `ty_m` 为正；雷达在相机前方则 `tz_m` 为正。量一下即可，几厘米的误差后面用角度补。
3. **偏航**。人站在画面正中（绿框中心接近 `cx`）。若黄点在人的右边，说明雷达方位偏了，减小 `yaw_deg`；黄点在左边就增大。正 yaw 表示雷达相对相机往左看。也可以在板子上临时算一个初值：`python3 -c "from vision.config import load_config; from vision.geometry import suggest_yaw_deg; c=load_config('config/fusion.json'); print(suggest_yaw_deg(雷达x, 雷达y, 框中心u, c))"`。这个初值忽略了平移，`tx` 较大时只做参考。
4. **高低**。黄点应该落在躯干上。点偏上就减小 `person_aim_height_m` 或减小 `pitch_deg`；点偏下就反过来。`radar_mount_height_m` 填雷达离地高度。二维雷达没有 z，投影用的是 `person_aim_height_m - radar_mount_height_m`。
5. **时间**。人横向走动。黄点拖在身体后面时增大 `radar_time_offset_s`（雷达时间戳比相机更晚、数据更旧）。点跑到身体前面就减小，可以是负数。`camera_latency_s` 是相机从曝光到拿到帧的延迟，两个只需要重点调一个，建议动 `radar_time_offset_s`。超过 `max_time_skew_s` 的雷达帧会整帧丢掉，不要为了“总有点”把它放到 1 秒以上。
6. **门限**。跟错人：减小 `assoc_gate_px_x`（水平）和 `radar_gate_m`。老是配不上、黄点在框旁边：先确认 3–5 步，再略增大 `assoc_gate_px_y`（高度误差主要在垂直方向）。`mahalanobis_gate` 默认 9.21，约等于二维 99% 置信椭圆，一般不用动。
7. **航迹寿命**。人被挡住一会儿就丢：略增大 `max_coast_s`（默认 0.45 秒）。鬼影消不掉：减小它，或把 `min_hits` 从 3 提到 4。`require_vision_for_confirm` 保持 true，这样没有被人看到的雷达点不会变成稳定航迹。

调的时候看 `/tracks`。同一个人的 `id` 不应来回跳，`source` 在两个传感器都有时应是 `fused`。`range_m` 应接近雷达测到的距离，横向位置应跟着人在画面里的位置走，而不是跟着雷达较差的方位角走。
