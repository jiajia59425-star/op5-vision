# OP5 V3：COIN-D6 雷达与视觉融合 · 第一阶段

**交付性质：** 独立8100只读影子融合服务，保留已验证稳定的8093高速预测V2。

## 输入与数据格式（来自既有程序）
- 8081 `GET /state`：`live/found/updated/selected/selected_class/tracks[].box/width/height`，`updated`使用香橙派同机单调时间。
- 8092 `GET /api/scan`：`online/packets/error/points`，点为`[雷达设备角度°, 距离m, 强度]`，由独立扫描进程维护的bin缓存（最长约1.2秒）。
- 8093 `GET /api/status`：`yaw.angle`及双轴状态；它会向串行总线读寄存器，但**不会写电机寄存器**。
- 展示：8100 `GET /api/fusion`、`GET /api/health`、独立HTML。无 POST 路由。

## 算法
1. 只在YOLO目标ID、类别和检测框一致、帧新鲜时取得目标中心。
2. 使用针孔摄像机模型把目标中心映射为视线水平偏角，需要校准镜头HFOV。
3. 雷达固定底盘时：`radar_bearing = radar_zero + sign × (yaw + camera_bearing + camera_offset)`；雷达安装在运动云台上时不叠加yaw。方向和零位必须现场校准。
4. 把雷达点按角度窗、连续角度、距离差分组，优先匹配与视线方向相近的点簇。
5. 至少三个**不同扫描包序号**产生的相近距离才能显示稳定候选值。ID变更、距离跳变、离线、数据过期会拒绝匹配。
6. 云台高速转动时暂停身份关联，避免雷达扫描和视觉视线错位。

## 安全与解释边界
- 当前雷达点是几何反射，无“这是YOLO所选人的回波”的身份证明。多个物体同方位时会产生假关联。
- 没有雷达点逐点硬件时间戳、相机内参与雷达外参，不能进行精确硬同步或确定三维目标距离。
- 不参与8093电机闭环、不参与PX4履带车避障/运动，不作为安全关键判断。
- 8093当前双轴80℃/10s策略为用户临时测试设置，该策略未被修改，温度读数偶发异常的根因仍待排查。

## 后续验证
A. 8100三源读数稳定、V2跟踪速度无退化。
B. 明确雷达安装位置、摄像头水平视场角和零位，再开启几何候选匹配。
C. 在固定已知距离的单一静止目标下验证：距离偏差、方位偏差，转动云台反向是否正确。
D. 多物体、遮挡、目标ID切换、雷达断线、云台高速旋转，验证拒绝错关联。
E. 需要提升为可靠控制前，另行添加相机/雷达外参标定、严格时间戳及独立硬件保护。
